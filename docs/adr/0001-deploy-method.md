# ADR-0001. Способ развёртывания приложения

**Статус:** принято
**Дата:** 2026-10-05

**Контекст**
Для доставки новых версий веб-приложения TimeCapsule на сервер EC2 требуется выбрать надежный метод. Необходимо обеспечить консистентность кода, автоматическое обновление сторонних зависимостей (через Composer) и безопасное применение изменений структуры базы данных, минимизируя при этом влияние человеческого фактора во время релизов.

**Решение**
Используем bash-скрипт `deploy.sh`, размещенный на сервере, который запускается удаленно с локального компьютера разработчика через SSH одной командой (Вариант B). Скрипт использует `set -euo pipefail` для остановки при ошибках и последовательно выполняет загрузку кода (`git pull --ff-only`), обновление библиотек, инициализацию БД и перезапуск `php-fpm`.

**Рассмотренные альтернативы**
1. **Копирование файлов через `scp`:** Отклонен. Способ не позволяет отслеживать текущую версию кода на сервере, требует ручной синхронизации удаленных/измененных файлов и не решает проблему установки зависимостей (папку `vendor` пришлось бы копировать целиком, что неэффективно).
2. **Ручной `git pull` на сервере (Вариант A):** Отклонен. Метод требует интерактивного подключения к серверу и ручного ввода 4-5 команд подряд. Существует высокий риск человеческой ошибки (разработчик может забыть запустить `composer install` или перезапустить службу `php-fpm`, что приведет к фатальной ошибке приложения).

**Последствия**
* Плюс: Процесс деплоя становится быстрым, воспроизводимым и безопасным. Риск пропустить важную команду исключен.
* Плюс: Разработчику не нужно тратить время на вход в консоль сервера, а результат деплоя (логи скрипта и хэш коммита) выводится прямо в локальный терминал.
* Минус: Приложение кратковременно работает нестабильно в процессе замены файлов и загрузки библиотек, так как данный метод не реализует бесшовное развертывание (Zero-downtime deployment).
